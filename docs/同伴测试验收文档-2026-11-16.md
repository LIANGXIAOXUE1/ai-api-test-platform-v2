## 1. 交付内容和范围

| 仓库 | 内容 |
| --- | --- |
| https://github.com/LIANGXIAOXUE1/ai-api-test-platform-v2 | Vue3/TypeScript/Vite前端，Go net/http后端，PostgreSQL数据，Agent、模型测评、MCP和验收脚本 |

模型池、Agent配置在平台内跨项目共享；接口、用例和执行记录按项目隔离。**共享指同一平台实例内共享，不是从GitHub自动获取作者的模型Key和数据库。**

两仓库与运行依赖足够验证平台基础功能和云盘核心链路；真实模型语义、模型发现和测评必须由测试者提供有效部署名/URL/Key和额度。云盘前端、OSS/MinIO、AI文档摘要（CLOUD_DISK_AI_API_KEY）和其他第三方集成需另配/另测。核心16步通过不等于所有OpenAPI接口、UI、安全或性能全通过。

验收状态使用 PASS（实际符合预期）、FAIL（实际不符）、BLOCKED（缺前置条件/依赖）、待执行。未执行不能填PASS。模板所有实际结果留空。

## 3. 一次启动两个项目（推荐）

先在一个空父目录执行，两个文件夹保持并排。下面命令可用于PowerShell或支持Git/Docker的终端：

```sh
git clone --depth 1 https://github.com/LIANGXIAOXUE1/ai-api-test-platform-v2.git
git clone --depth 1 https://github.com/LIANGXIAOXUE1/cloud-disk.git
cd ai-api-test-platform-v2
```

Windows PowerShell复制本地环境样例：

```powershell
Copy-Item .env.acceptance.example .env.acceptance
docker version
docker compose version
docker info
docker compose --env-file .env.acceptance -f deploy/docker-compose.acceptance.yml up -d --build
docker compose --env-file .env.acceptance -f deploy/docker-compose.acceptance.yml ps
```

macOS/Linux复制用 `cp .env.acceptance.example .env.acceptance`。已有env不要覆盖。端口被占用时在该文件改 `PLATFORM_WEB_PORT`、`CLOUD_DISK_PORT`，只改主机映射，不改内部云盘8082。其他目录可通过 `CLOUD_DISK_SOURCE` 指向云盘根目录（相对路径按Compose文件位置解析，推荐绝对路径）。不要同时再启动云盘独立Compose。

首次会从源码构建Go服务、npm前端和Maven云盘，等待依赖健康。失败先检查构建日志和Docker网络代理；浏览器能上网不代表Docker引擎已使用代理。禁止靠重置数据库处理拉镜像失败。

| 用途 | 默认地址/账号 |
| --- | --- |
| 浏览器平台 | http://127.0.0.1:5177/；平台登录用户 `local`，演示密码 `local-demo-password-change-me`（可在env修改） |
| 浏览器云盘OpenAPI | http://127.0.0.1:8082/v3/api-docs；接口文档8082/doc.html |
| 平台后端调用云盘 | `http://cloud-disk:8082`；任务OpenAPI为同地址 `/v3/api-docs` |
| 云盘业务账号 | 新环境没有作者账号；任务自动注册，或用户先调用register后自行填已有账号 |

**平台登录是访问测试工具的登录；云盘登录是被测业务接口的登录，两种账号不同。** 在平台内登录表单填写账号，当前无需注册。平台采用单个配置管理员的共享实例，所有项目/模型/记录可由该账号管理；没有独立用户空间或角色分级。助手审批权限另行控制，不是操作系统权限。会话有效8小时，侧边栏退出会注销当前会话；关闭标签页不等于退出，后端重启需重新登录但数据保留。 Docker里的localhost指容器自己，不能直接使用浏览器localhost作为后台目标。云盘根路径404不代表OpenAPI或后端不工作。

首次导入OpenAPI是文件：下载JSON到本机，修改 `servers` 为 `[{"url":"http://cloud-disk:8082"}]` 后导入。自动冒烟脚本自动做这一步。项目测试任务可直接填内部OpenAPI地址，不等同于文件导入组件支持URL。

## 4. 数据库与数据复现

| 系统 | 组件 | 持久化/初始化 |
| --- | --- | --- |
| 平台 | PostgreSQL16，`api_test`，`api_user` | 启动迁移建表，独立验收卷保存项目、任务、历史、模型配置等 |
| 平台 | 加密密钥文件 | acceptance_platform_keys卷保存；备份恢复时与数据库一同保留 |
| 云盘 | MySQL8，`private_aggregator` | 空卷首次执行云盘sql/init.sql，包含thumb_path字段；不提供作者数据和账号 |
| 云盘 | Redis7 | 登录Token等缓存；本次验收可以重新登录获取 |
| 云盘 | RabbitMQ3 | 异步队列；默认不发布管理端口 |
| 云盘 | 文件卷 | 保存真实上传字节；必须和MySQL记录一起保留/备份 |

原版历史数据库如缺thumb_path，应先备份检查后执行 `sql/migrations/20261110_file_thumb_path.sql`；空卷已有该字段，不重复跑迁移。重启不会重新执行init.sql。

演示env默认密码仅限127.0.0.1本机验收。仓库没有作者API密钥、数据库快照、原始测试账号或旧报告。使用真实模型时自行配置，不能把Key写在验收文档/提交Git。

保留数据停机/恢复：

```sh
docker compose --env-file .env.acceptance -f deploy/docker-compose.acceptance.yml stop
docker compose --env-file .env.acceptance -f deploy/docker-compose.acceptance.yml start
```

不要用 `down -v` 清掉验收记录或密钥。需要另建干净环境时用另一个Compose project name并改主机端口，保留旧卷。

## 5. 先跑零模型费用自动冒烟

```sh
docker compose --env-file .env.acceptance -f deploy/docker-compose.acceptance.yml --profile checks run --rm smoke
```

结果保存到平台 `.runtime/peer-acceptance/<时间-编号>/`：

- `acceptance.md` / `acceptance.json`：平台16项HTTP检查及云盘16步骤，各项实测状态。
- `cloud-run.json` / `cloud-report.md` / `cloud-report.json`：对应云盘runId的原始脱敏结果和导出。
- 退出码0表示脚本所覆盖项目都通过；1表示失败、阻塞或未执行，查看原因，不能只看容器退出。

脚本不调用付费模型，创建唯一项目和唯一云盘测试账号，文件只用本次样本，软删除后还原；不会清库或永久删除。测试账号、目录和还原文件留作证据；可在后续人工检查后按本次资源清理。

若主机已装Python，也可以执行 `python scripts/verify-acceptance.py --env-file .env.acceptance`；更改端口时显式加 `--base-url http://127.0.0.1:新平台端口 --cloud-doc-url http://127.0.0.1:新云盘端口/v3/api-docs`。后台目标 `--cloud-base http://cloud-disk:8082` 不变。

SM-12只验证未配置助手明确提示；已有真实配置时会标BLOCKED避免费用。脚本API验证不包含页面布局/下载交互；这些由下表人工补测。

## 7. 云盘流程为什么能自动测

项目测试页选择账号：自动生成并注册 / 手填新账号注册 / 已有账号登录；文件：自动2KB样本 / 自己提供最多5MB测试样本。预览计划可审核参数，再确认执行。登录结果提取 `data.token`，后续头 `cloud_disk_token: {{token}}`；目录ID、文件ID、回收记录ID按依赖传递，上传与下载、还原后的文件用SHA256验证。

启动依赖与业务验收是两个阶段：一体化Compose先启动MySQL/Redis/RabbitMQ和应用；平台随后发业务请求。16步没有专门验证RabbitMQ投递、消费或重试，也没有通用异步状态轮询能力。若验收异步文件处理，需要另列“提交任务→获取任务ID→轮询至完成/超时→核对结果”的用例及实现，不将容器健康当作消息业务通过。

如果登录失败，创建目录/上传等依赖步骤会被标阻塞；独立的未登录检查仍可能执行。这不是“未登录也测成功”。HTTP200只是传输成功，目录重名等要按业务码和断言判断。

## 8. 真实模型专项

模型池填测试者的真实URL、供应商、原始部署名和Key并验证；给助手选择已验证模型。容器访问外部模型如被安全策略拒绝，将**精确模型主机或URL**加到 `.env.acceptance` 的 `PLATFORM_ALLOWED_TARGETS`（保留 `http://cloud-disk:8082`，逗号分隔），重新创建backend服务。不要放开任意地址访问。涉及费用由测试者确认后执行。

EV-08～EV-10、EV-12～EV-14可使用受控、兼容聊天协议的测试桩核对故障/用量/排队行为；它属于协议与执行器测试，不代替真实模型质量验收。未提供测试桩或模型条件时标BLOCKED，不能靠想象填通过。只有收到测试者明确授权后才运行付费模型，并记录候选和辅助评审调用数量。

业务测评用文本模型即可演示短视频**脚本与分镜**，不需要视频生成订阅；不能说已测视频质量。另测企业知识问答、客户信息提取。对照原始回答核对事实/格式/时长，Token来源与人审意见保留；无法量化的检查需人工复核，小样本只支持本次场景结论。

## 11. 常见阻塞

| 现象 | 处理 |
| --- | --- |
| GitHub/Docker Hub超时 | 检查Git和Docker各自的网络/代理；Docker错误若写没有HTTPS代理，浏览器代理不能替代它 |
| 云盘构建缺JAR | 使用仓库新Dockerfile从源码构建，不复制作者target；原生方式先mvn verify |
| MySQL连接失败/字段缺失 | 查看云盘/mysql日志，确认目标库和卷；旧库先备份再按迁移处理，不重置原数据 |
| 云盘根路径404 | 检查/v3/api-docs和doc.html；后端容器未打包前端 |
| 平台登录反复401 | 检查本地env里的平台登录，区别云盘测试账号 |
| 登录业务失败 | 新环境先注册或选自动账号；查看code和message；不要让依赖步骤假通过 |
| 模型报未配置/401/429 | 配置测试者真实模型、检查Key/部署名/余额/限流；对应项目阻塞或失败，不规则兜底 |

| 报告下载看不到 | 看浏览器下载列表/Downloads；若客户端浏览器限制下载，用脚本导出的本地报告作为补充证据 |
