# 五项修复与生产上线说明

生产配置参考，文档统一修订2026-11-16。第1节保留11月12日的验证证据，不表示完成当前所有测评收尾项。测试团队先读[交付清单](测试团队交付清单.md)；完整构建、真实模型与目标环境上线仍须验收。

适用于由管理员管理的课设或小团队演示平台。平台的助手操作权限控制任务是否需要审核；平台登录控制谁能访问系统。这两项是不同层面的权限。

## 1. 本轮完成的五项修改

## 2. 当前本机验收入口

将平台和云盘克隆到同级目录，先启动Docker；完整依赖与操作见[统一验收指南](同伴测试验收文档-2026-11-16.md)。当前启动器使用一体化容器方案：

```powershell
./scripts/start-local.ps1 -RunSmoke
```

可用参数为CloudDiskRoot、FrontendPort、CloudDiskPort、RunSmoke。旧CloudDiskInDocker/CloudDiskJavaImage参数已经移除；平台后端内部端口8080不对主机发布。浏览器默认5177，云盘文档8082，平台后台目标http://cloud-disk:8082。平台登录从本地.env.acceptance读取；无需先部署服务器。

本机验收Compose和正式生产Compose用途不同；本机只发布127.0.0.1。以下是部署人员后续操作，当前测试团队不要在基线验收中直接发布公网。

## 3. 正式部署步骤

1. 准备一台能访问Docker Hub和npm的Linux服务器，安装Docker Compose；准备域名，将DNS指向服务器。
2. 导出或留档本次源代码与锁文件。可以运行`./scripts/export-release.ps1`生成仅包含源码/部署文件的快照；不会带上docs/KEY.txt、本机数据库、密钥和日志。
3. 在最终服务器上生成配置。脚本需要PowerShell 7；如使用Linux shell，按照production.env.example自行创建相同变量及受保护密码文件。不要把Windows绝对路径原样复制到Linux。

```powershell
./scripts/setup-production.ps1 `
  -Domain api-test.example.com `
  -AllowedTargets 'https://api.deepseek.com,https://your-gateway.example,http://host.docker.internal:8082'
```

生成目录默认`.runtime/production`。数据库密码与登录密码为随机值，脚本不输出密码，重复运行保留原密码。平台密码在该目录的secrets/platform-password.txt，用户自行查看保存。

目标清单填写完整来源`协议://主机:端口`，不填写/v1或请求路径。需要添加模型供应商、OpenAPI来源、被测项目来源。生产模式不会允许任意公网地址，内网地址也需明确列入；云元数据和链路本地地址即使写入清单仍被拒绝。

```powershell
$config = '.runtime/production/production.env'
docker compose --env-file $config -f deploy/docker-compose.production.yml config --quiet
docker compose --env-file $config -f deploy/docker-compose.production.yml build
docker compose --env-file $config -f deploy/docker-compose.production.yml up -d
docker compose --env-file $config -f deploy/docker-compose.production.yml ps
```

只对公网开放80/443；Caddy自动申请HTTPS证书。数据库和后端没有主机发布端口。首次打开平台内登录页填写配置账号；首次空库env创建管理员；已有账号密码以数据库为准，在平台内修改。管理员创建测试员/只读用户并分配项目，未开放自助注册；不是被测业务账号。侧边栏退出按钮撤销当前会话；关闭标签页不等于退出。服务端会话8小时后失效，后端重启需要重新登录。正式环境Cookie为Secure，必须通过HTTPS访问。登录入口一分钟最多10次尝试，超过后等待1分钟；反向代理后的额度按代理连接共享。

现有数据迁移须在启动后端之前恢复数据库及配套密钥。更改密码文件不会自动更改已有PostgreSQL卷的密码，不能重新运行初始化来代替改数据库密码。

## 4. 被测项目只要启动，不要求部署

平台与被测项目在同一机器时，填写可达的本机来源；Docker后端使用host.docker.internal。Linux服务器上的被测程序需要绑定可由容器访问的地址，并用防火墙限制来源。

如果平台在云端、云盘在你的电脑，云端不能访问你电脑的localhost。可以用受保护的VPN/私网连接，让平台访问电脑的测试地址，再将这个确切来源加入PLATFORM_ALLOWED_TARGETS。也可以保持平台与被测项目都在本机运行。

统一请求客户端不使用HTTP_PROXY/HTTPS_PROXY自动代理，避免代理绕过IP校验。需要代理才能访问的模型，应使用服务器已配置的VPN/TUN网络路径；不能以关闭目标限制作为解决方法。本机Docker拉镜像的代理是Docker自己的设置，与平台请求客户端不同。

## 5. 备份与恢复

本机原生后端：

```powershell
./scripts/backup-platform.ps1
./scripts/restore-platform.ps1 -BackupDirectory '.runtime/backups/实际备份目录'
```

生产Compose：

```powershell
./scripts/backup-platform.ps1 `
  -ComposeFile deploy/docker-compose.production.yml `
  -EnvFile .runtime/production/production.env -ContainerKey
```

备份包含database.dump、project-test.key、SHA256清单，目录权限受限。恢复脚本先验证校验和，只创建pulse_restore_开头的独立数据库，不覆盖现有平台。恢复密钥放在.runtime/restored/对应库名。验证独立后端可以读取模型、任务和报告后，在维护窗口决定是否切换数据库与密钥目录。

备份含敏感数据，应保存到受控位置。模型池Key与项目任务私有凭证已加密；单接口用户填写的请求体/响应记录仍可能含业务敏感数据，不应将数据库备份视为可公开材料。

## 6. WorkBuddy MCP连接

仍为本地stdio适配器，由平台服务器执行工具。新增环境变量：

```json
{
  "PULSE_API_URL": "https://api-test.example.com",
  "PULSE_API_AUTH_USER": "owner",
  "PULSE_API_AUTH_PASSWORD_FILE": "本机受保护的登录密码文件绝对路径"
}
```

远程凭证连接要求HTTPS。适配器拒绝地址跳转，避免平台密码传到其他来源。写操作保留既有confirm机制，目标请求仍由平台的统一策略控制。

## 7. 发布前最终验收

- 正式域名：匿名页面/资源/API被拦截，登录后可用；证书有效。
- 内置Echo正常200、无Token的demo/auth预期401通过、错误业务断言失败。
- 新建测试任务、模型配置、历史及导出可保存，重启后可打开。
- 供应商真实Key验证成功，助手使用真实模型；临时错误配置只报错，不生成规则结果。
- 云盘已启动，注册→登录→Token传递→文件操作的核心流程实际通过。
- 允许清单内服务可达，不在清单的目标被拒绝。
- 数据库和配套密钥备份、独立恢复通过。

以上是最终环境验收要求。源代码测试或本机验证通过，不等同于新服务器全部验收完成。


## 8. 用户权限上线检查

管理员应设置独立强密码，并为测试团队创建限定项目的账号。测试员自动执行默认关闭，需要时单独授权；只读用户不能执行或调用付费模型。公共模型池与助手配置只能由管理员修改。验证跨项目编号、批量/链路引用、CLI/MCP同等拒绝，以及报告脱敏和操作日志。平台用户、授权、密码哈希和操作日志保存在同一PostgreSQL备份中；env仅首次空库初始化，不能通过更改env覆盖已有密码。保留至少一个启用管理员。禁用不自动取消已接受的异步任务，必要时先停止任务。当前没有企业SSO、组织租户隔离、细粒度模型额度或操作系统权限管理。
