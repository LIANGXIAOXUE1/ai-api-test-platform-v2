## 2026-11-25：文档上传与生成反馈实测

上传成功只表示文件能被解析并保存，不表示一定能生成可执行测试。业务资料需要可验证的条件和预期；可执行请求还要匹配当前项目真实接口。没有统一文档模板或业务关键词门槛，由模型根据资料语义判断适用性，再由后端检查请求目录与断言类型。

| 场景 | 本次实际结果 |
| --- | --- |
| 请求回显服务业务文档 | 已通过页面上传至“本地接口演示项目”，可预览完整文本；gpt-6.2-sol真实生成5条正常及边界可审核用例 |
| 保存和执行 | 5条已保存，caseId为14至18；均实际请求POST /api/demo/echo并返回200，共21/21条断言通过。首条经页面保存、载入、仅发送，后四条经同一平台接口保存执行 |
| 未约定的异常行为 | 损坏JSON、超大请求、并发限流未有明确业务预期，作为待补充项展示，不编造错误码；timestamp只检查字段存在，非空时间格式未被声称已自动验证 |
| 只有项目介绍、没有规则 | 文件可以上传；真实模型判断资料不足，返回cannot_generate及knowledge_document_has_no_rules；页面红色提示列出具体缺失资料与处理步骤，补充按钮可聚焦输入框 |
| 空文件 | 页面立即显示“文档上传失败：文件为空”，并提供重新选择文件入口 |
| 损坏DOCX | 后端返回400及document_parse_failed；页面持久展示无法提取文本的原因和恢复提示 |
| 无资料 | 未选文档且未填写补充资料时，返回knowledge_no_material及明确补充步骤 |
| 非法接口范围 | 权限层返回403，避免利用不存在或越权接口生成请求；这是预期负向请求，浏览器可能记录对应资源错误 |

实测期间发现模型会以原生JSON对象、数字或布尔值输出请求体/断言预期。现已在知识库模型输出适配层转换为编辑器可存储文本，保留JSON含义；单条格式错误不会丢弃其余合法用例。整批格式不合法则明确说明“模型返回的用例格式未通过校验”，不归咎于模型连接或资料上传。

自动校验覆盖：空文件、不支持ZIP、空白文本、无效UTF-8、二进制文本、损坏DOCX、超过12MB、文本超过120000字符；零结果、草稿、部分生成、完整生成的状态区分；原生JSON输出和部分格式错误的保留策略。后端7个包通过，前端14条测试通过，构建通过；独立测试数据库集成通过。已检查错误页面截图，实际操作没有JavaScript运行异常。
