# 请求回显服务业务验收说明

本文用于本地接口演示项目的知识库测试，规则来自平台内置的真实回显接口。

## 业务目标

用户提交JSON数据后，服务返回收到的数据，便于确认字段、值和结构在接口调用过程中是否完整传递。

## 接口范围

- 请求方式：POST。
- 接口路径：`/api/demo/echo`。
- 请求头：`Content-Type: application/json`。
- 请求体：JSON对象，可包含字符串、数字、布尔值、数组及嵌套对象。

## 已确认的成功规则

1. 提交有效JSON时，HTTP状态码应为200。
2. 响应包含`message`、`received`和`timestamp`字段。
3. 响应`message`应为`echo ok`。
4. 响应`received`应与请求JSON的数据内容一致，字段和值不被擅自改变。
5. 请求为`{}`时，响应`received`应为空对象。
6. 对有效JSON中的嵌套对象、数组、数字和布尔值，应保留对应结构与值。
7. `timestamp`为非空时间字符串。

## 测试数据

正常输入：`{"message":"hello","count":2,"enabled":true}`。

嵌套输入：`{"context":{"requestId":"demo-001"},"items":["a","b"]}`。

边界输入：空对象`{}`、空数组字段`{"items":[]}`、空字符串字段`{"message":""}`。

## 尚未确认的范围

本文没有约定损坏JSON、超大请求或并发限流的业务错误码。生成这类异常用例前，应先补充实际接口约定，不自行假设返回400或其他状态。

## 验收要求

依据上述成功规则生成正常与边界用例，写清请求体、字段断言和预期结果。没有文档依据的异常预期，应列为待补充信息。
