## 团队交回什么

1. 填好的CSV，记录PASS/FAIL/BLOCKED/待执行、实际值、执行人、日期和证据编号。
2. 自动冒烟结果及云盘/模型报告，保存对应runId、版本、环境、截图和请求响应证据；敏感字段脱敏。
3. 缺陷列表：用例编号、复现步骤、预期、实际、严重程度、证据、修复版本和重测结论。
4. 验收结论：本次执行/通过/失败/阻塞/未执行数，明确可接受范围及不建议上线的原因。

没有Key或测试桩时对应项BLOCKED；服务实际返回不符合预期时FAIL。不能因为缺条件把已承诺AI功能算通过；不能通过修改预期把缺陷变成成功。

## 上线顺序

基础预检 → 已知问题登记/修复 → 受影响项重测与AI专项 → 汇总验收 → 目标环境部署/复测。执行或评价逻辑在验收后改变，要重新验证相关项和核心冒烟。小规模受保护演示和企业多租户交付是不同范围。

旧日期方案用于解释设计演进，不作为本次操作标准。遇到冲突，以本清单、同日验收指南、同编号CSV为准；若代码仍达不到预期，登记缺陷。
