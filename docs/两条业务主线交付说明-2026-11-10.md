# 两条业务主线交付说明

本次仅扩展项目业务测试和模型测评，复用平台现有助手与公共模型池。单接口测试、图片接口、知识库、旧历史记录与 MCP 兼容接口保留。项目只要启动即可，不要求部署到服务器。

## 1. 项目测试：证明已完成项目的核心接口业务能跑通

入口：顶部“项目测试”，选择有 51 个接口的 `03-Cloud Disk 业务回归测试` 项目。

- 任务配置：目标地址、OpenAPI 地址或文件、测试目标、账号来源、文件来源、业务范围、审核/自动执行。
- 账号来源：随机生成并注册；用户填写新账号后注册；使用已有账号直接登录。
- 文件来源：自动生成 2048 字节文本，或用户提供不超过 5 MB 的样本。
- 流程来源：明确选中的 Cloud Disk 预置验收模板，或当前真实助手模型根据契约生成。模型调用失败不回退到规则草稿。
- 模型流程经过结构、依赖、地址范围和写资源校验；结构失败向模型反馈并允许修正一次。缺少资料时弹出补充信息窗口，填写后继续生成。
- Token、目录 ID、文件 ID、回收记录 ID 自动提取与传递。额外测试变量可在配置中补充。
- 逐项结果：通过、失败、阻塞、未执行；可展开预期、实际、请求、响应和脱敏变量。
- 任务可保存。打开历史仅读取报告；重新执行创建新报告。失败重跑复用原来的账号、文件与成功证据，只发起失败/阻塞步骤。
- 导出 Markdown / JSON。密码和运行私有上下文使用 AES-GCM 加密，密钥文件位于 backend/data，必须保留。

Cloud Disk 模板覆盖：注册 → 登录 → 创建目录 → 查询目录 ID → 重名拒绝 → 上传 → 查询文件及大小 → 下载 SHA256 → 重命名 → 查询核对 → 移入回收站 → 确认目录移除 → 查询回收记录 → 还原 → 下载核对 → 未登录拒绝。共 16 步，负向业务错误是符合预期的通过结果。

实际验证：首次查询目录返回 HTTP 200 / 业务 code 500，报告正确显示 5 通过、1 失败、10 阻塞。日志定位到云盘 MySQL 缺少 thumb_path。采用加列迁移修复，保留原数据；失败重跑后 16/16 通过。启用写资源来源校验后重新全跑仍为 16/16。失败原报告和后续报告均保留。另用真实助手模型生成注册/登录/错误密码/未登录访问流程，4 项中 3 项通过；错误密码响应为业务 code 500，与预期鉴权拒绝不符，单独报告为失败，没有修改断言把异常算作通过。

## 2. 模型测评：按客户任务比较文本模型

入口：顶部“模型评测”。模板包括短视频脚本与分镜、企业业务知识问答、客户信息提取。

- 填客户目标、已知事实、必须满足、样本与可选参考要点。
- 选择公共模型池候选和辅助评审模型，每个样本可重复 1–3 次。
- 短视频任务检查 JSON、分镜数量、画面/口播/字幕、规划总时长。信息提取检查约定字段及参考 JSON 的值，未知值可为 null。
- 事实与业务要求由模型辅助评价；每条语义结论保留原文片段。每段必须在真实输出中定位，否则保留“待复核”。模型评价不冒充程序校验或普遍准确率。
- 参考要点留在评价侧，避免把答案提供给候选模型。
- 显示真实耗时、上游 Token 用量；缺少上游用量时注明估算。价格未配置，不生成虚构费用。
- 对照表可查看原文和证据；人工复核需要理由并保存为新报告版本，原版本保留。
- 任务和执行历史可保存与导出。旧版记录保留原回答，关键词启发式数值不再作为准确率展示。

实际验证：通勤杯资料为 450ml / 280g，要求 6 段、30 秒、不编造性能。DeepSeek 与 gpt-5.6-luna 两个真实候选均返回有效脚本；新版证据协议下，各自 6 项检查均满足。该结果仅代表本次单样本任务，不代表模型在全部短视频业务上的优劣。已保存真实测评记录。

## 4. 边界

- 当前验证的是接口业务和数据流，不能据此证明网页、小程序或微信收银台交互正常。
- 短视频测评生成的是脚本/分镜文本，不需要视频生成订阅，也不评价视频成片、音画同步或真实配音时长。
- 外部支付、短信、真实验证码与第三方授权需要用户准备测试环境或信息，系统不能伪造成功。
- 写操作须绑定本次创建的资源；不自动清空回收站、永久删除、删除测试账号。测试资源保留供排查。
- 失败重跑沿用原成功证据并明确标注；若修改服务后要形成完整的新验收证据，应重新跑整个任务。
- 模型语义评价仍可能偏差，需要查看证据或人工复核；本次测试不等于覆盖全部接口、全部功能或专项安全测试。
- 这是本机开发工具，尚无对外多租户身份认证与操作人签名体系；不能直接作为公网企业权限平台部署。
- 单任务最多 80 步；文件 5 MB、响应 6 MB；项目任务并行 2 个。测评最多 20 样本、8 候选、3 次重复、80 个候选调用；并行 3 个调用任务。

## 5. 运行与演示

平台 http://localhost:5177/，平台 API http://localhost:8081/，云盘 OpenAPI http://localhost:8082/v3/api-docs。

再次启动可运行 scripts/start-local.ps1。它在后台启动本机服务，复用已监听端口，不弹终端窗口。Docker Desktop 需要已打开。

演示项目测试：选择正确 Cloud Disk 项目 → 项目测试 → 已保存任务与记录 → 打开“云盘交付前核心业务验收”最新报告。可以看到成功报告，也可打开首次失败记录展示数据库问题及后续阻塞；打开报告不会重复执行。

演示模型测评：同一项目 → 模型评测 → 已保存任务与记录 → 打开“通勤杯30秒脚本比较”新版报告 → 逐项比较 → 查看原文与证据。现场再次测试时复用任务，并选择仍可用的真实文本模型。

向客户解释：第一条线验证已经启动项目的核心接口业务是否按预期完成，并提供证据；第二条线按客户给定任务与标准比较模型输出，帮助筛选适合当前用途的候选。两条线都保留任务配置和真实记录，便于重复验证和交付沟通。
