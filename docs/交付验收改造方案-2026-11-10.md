日期：2026-11-10
状态：项目测试结构拆分已完成；冒烟与业务验收增强待后续实现。
平台仓库：D:/课设/ai-api-test-platform-v2

## 1. 最新范围：只完善项目测试功能

本方案替代此前扩大到整个平台的改造建议。

- 功能归属：现有「项目测试」功能，包含项目整体冒烟、业务用例执行及报告。
- 被测条件：项目已经启动，而且测试平台能访问它，例如本地 http://localhost:8082。无需部署上线，不要求域名、HTTPS、云服务器、发布流水线或构建号。
- 用户目的：项目写完并启动后，验证核心业务链路能否真正跑通。
- 其他功能：单接口测试、模型池、模型评测、现有助手界面、全站导航和样式保持现有行为。
- 代码整理：只抽离项目测试相关代码，调整必要接线；本轮不做全站组件迁移、全局框架更换或其他模块重构。
- 助手：沿用现有助手，通过一个任务入口调用项目测试模块；保留原有会话、配置和其他能力。
- 已完成项目测试模块的结构拆分，并通过构建、自动化测试及隔离模拟页面核验；没有向被测项目发送真实业务请求，也没有迁移数据库。结构与验证说明见[项目测试模块结构](项目测试模块结构.md)。

“验收”在这里表示项目完成后的整体自检。本地启动的项目可以使用同样的冒烟与用例机制，不以正式交付或上线为运行前提。

~~~text

        ↓

        ↓

        ↓

        ↓

        ↓

        ↓
查看哪些链路通过、失败或阻塞
        ↓
~~~

已有用例和账号配置时，直接执行，不需要每次重新生成或逐接口审核。

如果测试平台后端在容器里，localhost 指容器自身，目标地址需要设置为后端实际可访问的主机地址。这属于访问地址配置，不意味着要求用户重新部署项目。

## 3. 源码检查发现的相关基础与缺口

以下是源代码层面的检查结果，不是被测系统运行结果：

| 现有基础 | 项目测试需要完善的部分 |
| --- | --- |
| 只读连通性巡检 | 降为启动检查；收到 HTTP 响应不能代替业务链路通过 |
| 顺序链路与变量替换 | 保存整套用例；支持数组提取、类型保留和依赖状态 |
| 单步请求、断言、历史 | 增加项目测试任务记录、步骤归属、逐项证据及整套报告 |
| 浏览器公共环境文本 | 为项目测试新增按项目保存的目标地址和身份配置，不改变其他页面的环境功能 |
| 公共模型池与助手 | 复用配置；本次测试账号与运行 Token 不写入公共模型池 |
| OpenAPI JSON 基础导入 | 项目测试入口补文件/URL读取及所需契约解析，兼容原有导入行为 |
| 字符串 HTTP 请求体 | 项目测试执行器补 multipart 上传、二进制读取和哈希校验 |

已发现的关键执行问题：
1. 旧 execute 要求 HTTP 2xx，期望 401/409 的负向用例仍可能被判失败。
2. 旧链路界面发送时把每步断言固定为 HTTP 200。
3. 对象点路径提取不支持数组索引，不是完整 JSONPath。
4. 提取失败发生在单步入库之后，返回结果与数据库可能不一致。
5. 没有断言的请求被统计为 1/1，通过结果不适合直接用于项目验收。
6. 旧运行记录缺完整请求快照及逐条预期/实际值。
7. 相对 URL 的旧解析可能指向平台后端。新模块必须依据所选被测地址解析。

这些语义在项目测试模块内实现正确逻辑。对公共底层的必要抽取保留原接口兼容行为，不把新判定方式无差别套到其他模块。

## 7. Cloud Disk 示例用例

以现有云盘为首个验证对象，localhost:8082 只是历史示例地址，并不表示本轮确认它正在运行。

主链路：登录 → 创建唯一测试目录 → 上传 → 读取 → 删除 → 回收站查询 → 恢复 → 再次读取。

| 步骤 | 操作 | 验证结果 |
| --- | --- | --- |
| 1 | 登录并读取用户身份 | token 非空且可用，用户正确 |
| 2 | 创建本次目录，再按名称查询 | 目录唯一，获得 folderId |
| 3 | multipart 上传固定样本 | 返回 fileId，名称/大小/parentId 正确 |
| 4 | 读取真实文件内容 | 长度和 SHA-256 与原文件一致 |
| 5 | 删除后查询目录 | 原目录不再出现 fileId |
| 6 | 查询回收站 | 找到同一 fileId，获得 recycleId |
| 7 | 恢复并查询 | 原目录重新出现同一文件 |
| 8 | 再次读取实际内容 | 内容与上传前一致 |

使用专用测试账号；没有账号时先准备或注册。初始化账号与日常执行分开，避免每次制造新账号。只清理本次登记的资源 ID；清理失败显示残留情况。

补充业务用例：
- 未登录、错误密码、无效 Token 按契约拒绝。
- 账号 B 不能读取或修改账号 A 的文件。
- 同目录同名文件夹被拒绝，数量不增加。
- 重命名冲突不得覆盖原数据。
- 注册必填字段与密码长度校验。
- 根据实际范围选测分片上传、分享等功能；未覆盖项明确列出。

按当前源码：
- 登录 token 位于 data.token，鉴权头为 cloud_disk_token。
- createFolder 的 folderName/parentId 是查询参数。
- 创建返回 data.result="OK"，需要后续查询目录 ID。
- 同名冲突为响应体 code=409，控制器通常仍返回 HTTP 200。
- 未登录异常可能是响应体 code=401、HTTP 200。
- 回收站恢复使用 recycleId，不是原 fileId。

以上契约需与当前实际启动版本核对。正常/异常用例根据已确认需求判定，不能为了适应实现而悄悄改预期。

## 8. 通过、失败、阻塞怎样区分

- 收到响应：只表示请求有结果。
- 通过：请求/业务断言/必要提取均满足本用例预期。
- 失败：实际行为与预期不符。
- 阻塞：缺账号、样本或前置步骤失败，当前用例无法执行。
- 未执行/取消/执行错误：分别记录，不计为通过。
- 独立用例可继续，依赖失败的下游标为阻塞。
- 空用例集、无验证点、没执行不能得到“项目测试通过”。
- 存在未完成的必需用例，总结必须说明项目测试未完成。

示例（并非实际结果）：

~~~text
Cloud Disk 项目测试
目标：http://localhost:8082

冒烟用例：全部通过
业务用例：通过 10，失败 1，阻塞 1
失败：重命名冲突校验
阻塞：缺少第二个测试账号

结论：核心接口链路已跑通，业务用例尚未全部通过。
覆盖范围：后端业务接口；页面交互未验证。
~~~

执行配置与用例版本自动留快照；用户不用先填写发布版本或搭建部署流程。备注当前代码版本可选。

## 9. 助手的使用方式

> 我的云盘项目已经启动，地址是 http://localhost:8082。请使用这个项目已有的接口和测试账号，执行登录、上传、读取、删除恢复的冒烟测试，再执行保存的业务用例。缺少信息就让我补，最后给出结果和报告，只清理这次创建的数据。

复用现有模型池及助手配置。首次生成用例时明确预期与执行范围；已确认用例在相同授权范围内重复执行，不逐步索要确认。

模型理解需求、生成草稿、解释结果；项目测试执行器计算断言和报告。模型调用失败应明确提示，已保存用例仍可正常执行。模型不接收真实密钥，也不能随意调整历史结果或验收预期。

## 10. 边界

1. 本地启动即可；服务依赖需要正常运行，测试平台必须能访问启动地址。
2. API 业务链路通过不代表页面按钮、视觉与小程序交互全部通过。首期在报告中注明，可附简单人工检查项，不新建一套全站验收管理系统。
3. 若选择支付等第三方场景，模拟回调与真实支付分开报告；未配置的部分不能算通过。
4. OpenAPI 不能代替业务规则；缺少预期依据时需要补充说明。
5. 当前功能不自动改被测代码、不自动发布、不执行任意主机命令。
6. 重跑写请求要处理资源状态与重复操作，不做无限自动重试。
7. 测试账号和运行变量按项目/本次执行隔离；公共模型池保持公共。
8. 报告说明实际覆盖与未验证内容，不输出没有依据的“整个项目完全没问题”。

## 11. 实施与验证顺序

1. 抽离现有项目测试状态、页面与处理器，保持其他模块行为。
2. 建立本模块配置、用例和运行记录，兼容旧巡检历史。
3. 实现正确的业务判定、变量传递、文件链路与本次资源清理。
4. 接上进度、详情窗、历史及报告。
5. 现有助手按需增加一个项目测试调用入口，不改其他助手能力。
6. 使用已启动的云盘验证成功、业务失败、配置阻塞三个场景。

验证重点：
- 负向用例能正确通过，HTTP 200 的业务错误不会被误报。
- 提取失败实时状态与历史一致；数组、数值、缺失字段正确处理。
- 刷新后任务仍可查看，历史预期和证据不随编辑改变。
- 文件上传/下载实际字节正确；项目间 Token 不串用。
- 原单接口测试、模型池、模型评测和助手原有流程仍可使用。
