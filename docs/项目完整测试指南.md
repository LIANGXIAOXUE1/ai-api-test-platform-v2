### Echo 是什么？

`回声接口 / Echo` 是平台内置的零成本测试接口。发送：

```json
{"message":"hello"}
```

它会返回对应的 JSON 内容。它不是业务接口，而是用来证明“请求配置 → 平台后端执行 → 响应解析 → 断言 → 历史保存 → 回归比较”这条平台主链路正常。

### 断言是什么？

断言是“本次请求什么结果才算通过”的规则。例如：

```text
状态码等于 200：接口必须成功返回 200
JSON 存在字段 data.token：登录成功必须返回 Token
状态码等于 401：未登录访问受保护接口时才算符合预期
```

因此，返回 200 但缺少业务字段仍可以判定失败；未登录接口返回 401 则可能判定通过。断言是批量测试与回归比较能够自动判断结果的基础。

1. 进入“回归”；
2. 找到刚才保存的 Echo 用例；

### 4.3 DeepSeek 真实 API 测试（建议必须做）

这一步验证的不是“小助手聊天”，而是平台能否把 DeepSeek 当作被测 API，记录真实状态码、耗时、响应结构和断言结果。

1. 新建平台项目：`02-真实大模型与图片接口`；
2. 进入“测试台”，新建接口，填写：

```text
名称：DeepSeek 对话接口
方法：POST
URL：https://api.deepseek.com/chat/completions
Header：Authorization: Bearer <自己的 DeepSeek API Key>
Header：Content-Type: application/json
```

3. 请求体粘贴以下内容：

```json
{
  "model": "deepseek-chat",
  "messages": [
    {
      "role": "user",
      "content": "请用一句话解释什么是 API 回归测试。"
    }
  ],
  "temperature": 0.2,
  "stream": false
}
```

4. 配置断言：`状态码等于 200`、`JSON 存在字段 choices`；
5. 点击“仅发送”，确认响应中有 `choices[0].message.content`；
6. 结果正常后点击“发送并保存”，让这次真实请求进入历史与回归记录。

> Agent 配置页中的 API Key 只填原始 Key，因为平台会自动补 `Bearer `；测试台的 Header 则应按上面示例明确填写 `Bearer <Key>`。

### 4.5 Azure GPT Image 图片接口测试（只做一次即可）

Azure GPT Image 是图片生成 API，不是聊天模型。应在测试台按普通 HTTP/多模态接口测试，**不要**把它配置成助手模型或加入模型评测、批量测试与回归重放，以免产生不必要的重复费用。

### 5.3 推荐的真实接口测试顺序

#### A. 注册用户

```http
POST http://host.docker.internal:8080/api/auth/register
Content-Type: application/json

{
  "username": "apitest_demo",
  "password": "Test123456",
  "nickname": "接口测试用户",
  "email": "apitest_demo@example.com"
}
```

断言：HTTP 状态码 `200`；JSON 中 `code` 为 `200`，`message` 为 `success`。

#### B. 登录并取得 Token

```http
POST http://host.docker.internal:8080/api/auth/login
Content-Type: application/json

{
  "username": "apitest_demo",
  "password": "Test123456"
}
```

断言：HTTP 状态码 `200`；JSON 存在字段 `data.token`。从响应复制 Token，后续受保护接口增加 Header：

```text
cloud_disk_token: <复制的 Token>
```

#### C. 验证鉴权

```http
GET http://host.docker.internal:8080/api/file/list?page=1&pageSize=20
```

先不带 Token 发送，预期鉴权失败（一般为 HTTP `401`）；再带 Token 发送，预期成功。平台应把失败分类为“鉴权失败”。

#### D. 验证同名文件夹规则

```http
POST http://host.docker.internal:8080/api/file/createFolder?folderName=API-Test
cloud_disk_token: <复制的 Token>
```

第一次预期成功：HTTP `200`，响应 JSON 的 `code` 为 `200`。使用完全相同的参数第二次发送：该项目当前会返回 **HTTP 200，但 JSON 内 `code: 409`**，并带有“目标位置已存在同名文件夹”的 `message`。这也是一次非常有价值的测试发现：业务错误码和 HTTP 状态码没有统一。

因此第二次的断言应优先检查 JSON `code = 409` 与 `message` 包含“同名”，不要只断言 HTTP 409。它是最适合保存为回归用例的业务规则测试。

## 6. 链路测试：分片上传

在“链路”页按顺序加入：

```text
登录
→ 从响应提取 token
→ 初始化分片上传
→ 从响应提取 uploadId
→ 上传分片
→ 查询进度
→ 合并分片
```

变量配置示例：

```text
token: 登录响应中的 data.token
uploadId: 初始化上传响应中的 data.uploadId
```

后续步骤的 Header 或 Body 中使用：

```text
cloud_disk_token: {{token}}
{"uploadId":"{{uploadId}}"}
```

预期：每一步都有独立状态码、耗时和结果；链路页显示提取出的变量并对 Token 等敏感值脱敏。

## 9. 常见问题

### Docker Desktop 未启动

现象：`docker compose up` 提示无法连接 Docker Engine。  
处理：打开 Docker Desktop，等待状态变为 **Engine running** 后重试。

### Docker 要不要登录

不用。Docker Desktop 显示 **Engine running** 后即可运行本地已有容器。只有拉取私有镜像、推送自己的镜像，或 Docker Hub 要求身份验证时才需要登录。当前更常见的启动阻塞原因是网络无法访问 Docker Hub，而不是未登录。

### Cloud Disk 接口连接失败

检查顺序：

1. 浏览器能否访问 `http://localhost:8080/v3/api-docs`；
2. Cloud Disk 的 Docker 服务是否全部 `Up`；
3. 本平台后端是否通过 Docker 运行；若是，将被测地址改为 `http://host.docker.internal:8080`；
4. 检查 8080 端口是否被其他服务占用。

### 401 鉴权失败

确认已经先调用登录接口，且 Header 名称为 `cloud_disk_token`，Token 没有复制多余空格或引号。

### 重复注册失败

这是正常现象。更换 `username` 后重试，或把“重复用户名”作为异常测试用例保存。

### Azure 图片接口返回 404

检查 Azure Portal 中图片模型的 **部署名** 是否与 URL 完全一致；不要写模型显示名。其次确认 endpoint、API Key 和部署来自同一个 Azure OpenAI 资源，并使用该资源支持的 API Version。
