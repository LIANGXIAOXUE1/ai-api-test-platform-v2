# AI API 智能测试与回归分析平台：完整测试指南

> 本指南用于验证平台能否从“配置接口”到“真实执行、保存结果、回归比较”完整跑通。  
> 推荐先完成平台内置接口冒烟测试，再使用 Cloud Disk 项目进行真实业务接口测试。

## 0. 测试目标

本次测试验证以下能力：

```text
项目与接口管理
→ 请求配置与真实发送
→ 状态码 / 断言 / 错误诊断
→ 历史保存与回归比较
→ 业务规则生成测试场景
→ 多接口链路变量传递
→ AI 助手生成请求草稿
```

## 1. 启动本平台

### 1.1 前置条件

- Docker Desktop 已启动，状态为 **Engine running**；
- 端口 `5174`、`8081`、`5433` 未被其他程序占用；
- 首次构建需要能访问 Docker Hub 拉取基础镜像。

### 1.2 Docker 启动

在项目目录执行：

```powershell
cd D:\课设\ai-api-test-platform-v2\deploy
docker compose up -d --build
docker compose ps
```

正常时应看到三个服务：

```text
pulse-api-v2-frontend-1   5174
pulse-api-v2-backend-1    8081
pulse-api-v2-db-1         5433
```

浏览器打开：

```text
http://localhost:5174
```

### 1.3 不用 Docker 时的前端预览

如果只想修改或查看前端样式：

```powershell
cd D:\课设\ai-api-test-platform-v2\frontend
npm install
npm run dev -- --port 5177
```

打开 `http://localhost:5177`。注意：前端开发服务仍需要 `http://localhost:8081` 的后端才能加载真实项目和接口数据。

## 2. 平台内置接口冒烟测试

此步骤不依赖 Cloud Disk，目的是先确认平台自身的“配置 → 发送 → 断言 → 保存”流程可用。

### 2.1 测试 Echo 接口

1. 进入“测试台”；
2. 左侧选择 `回声接口 / Echo`；
3. 保持以下默认内容：

```text
方法：POST
URL：/api/demo/echo
Body：{"message":"hello from api tester"}
断言：状态码等于 200
```

4. 点击“仅发送”。

预期结果：

- 响应区显示 `200`；
- 可以看到耗时、响应内容和断言结果；
- 页面无报错提示。

### 2.2 验证错误诊断

将 URL 临时改为：

```text
/api/not-found-demo
```

发送后预期看到 `404`，平台应提示“接口地址不存在”，并建议检查 URL、接口版本或网关路由。测试结束后点击“恢复接口默认值”。

### 2.3 保存测试用例

恢复 Echo 接口后，点击“发送并保存”。

预期结果：

- “历史”页面出现本次记录；
- “回归”页面出现对应保存用例；
- 历史记录包含状态码、耗时、执行时间和通过/失败状态。

## 3. 回归测试验证

1. 进入“回归”；
2. 找到刚才保存的 Echo 用例；
3. 点击“查看差异”，确认可看到当前基线；
4. 点击“重新执行并比较”；
5. 执行完成后，回到“回归”查看最新记录和前后差异。

建议人为制造一次差异：把接口 URL 改为不存在地址后“发送并保存”，再重新执行原用例。此时可对比正常 `200` 和失败 `404` 的状态变化、响应结构和耗时变化。

## 4. AI 助手测试

### 4.1 规则 Agent（无需 API Key）

1. 在测试台选择 Echo 接口；
2. 点击右下角悬浮“AI 助手”；
3. 输入：

```text
测试这个接口是否可用，并检查返回 JSON。
```

4. 点击“发送给 AI”；
5. 查看 Agent 执行计划和请求草稿；
6. 点击“应用到测试台”；
7. 回到测试台检查 URL、Body、断言，再由用户点击发送。

预期：助手只生成草稿，不会未经确认发送请求或修改接口。

### 4.2 接入 DeepSeek（可选）

在“配置”页填写：

```text
Chat Completions 地址：https://api.deepseek.com/chat/completions
模型：deepseek-chat
鉴权 Header：Authorization
API Key：自己的 DeepSeek API Key
```

保存后重复 4.1 的测试，验证 Agent 是否从“规则 Agent 模式”变为真实模型驱动。**不要将 API Key 写入 README、提交到 GitHub 或发送给他人。**

## 5. Cloud Disk 真实接口测试

Cloud Disk 是本平台的真实演示项目，源码位于：

```text
D:\课设\测试仓库\cloud-disk
```

### 5.1 启动 Cloud Disk

```powershell
cd D:\课设\测试仓库\cloud-disk
docker compose up -d --build
docker compose ps
```

确认 OpenAPI 文档可访问：

```text
http://localhost:8080/v3/api-docs
```

将该地址返回的 JSON 保存为 `cloud-disk-openapi.json`。

> 若本平台后端以 Docker 方式运行，请在本平台配置 Cloud Disk 地址时使用 `http://host.docker.internal:8080`，不要写 `http://localhost:8080`。因为请求由平台的后端容器发出，此时容器内的 localhost 不是 Windows 主机。

### 5.2 导入接口与规则文档

1. 在本平台新建项目：`Cloud Disk 接口测试`；
2. 在“测试台”左侧点击“导入 OpenAPI”，选择 `cloud-disk-openapi.json`；
3. 进入“知识库”；
4. 上传以下文档：

```text
demo-docs/cloud-disk/01-CloudDisk-业务规则.md
→ 文档类型选择：业务规则

demo-docs/cloud-disk/02-CloudDisk-接口测试操作手册.md
→ 文档类型选择：接口契约
```

5. 勾选业务规则文档，点击“根据规则生成测试用例”。

预期：系统显示注册校验、鉴权、同名文件夹、分片上传、回收站恢复等场景，并展示规则依据。

> 当前版本中，业务规则生成的用例先以“草稿”形式展示；可手动将关键请求填入测试台后保存执行。“生成用例后直接一键保存并批量执行”是下一阶段优化项。

### 5.3 推荐的真实接口测试顺序

#### A. 注册用户

```http
POST http://host.docker.internal:8080/api/auth/register
Content-Type: application/json

{
  "username": "apitest_demo",
  "password": "Test123456",
  "nickname": "接口测试用户",
  "email": "apitest_demo@example.com"
}
```

断言：状态码 `200`；响应包含 `success`。

#### B. 登录并取得 Token

```http
POST http://host.docker.internal:8080/api/auth/login
Content-Type: application/json

{
  "username": "apitest_demo",
  "password": "Test123456"
}
```

断言：状态码 `200`；JSON 存在字段 `data.token`。从响应复制 Token，后续受保护接口增加 Header：

```text
cloud_disk_token: <复制的 Token>
```

#### C. 验证鉴权

```http
GET http://host.docker.internal:8080/api/file/list?page=1&pageSize=20
```

先不带 Token 发送，预期鉴权失败；再带 Token 发送，预期成功。平台应把失败分类为“鉴权失败”。

#### D. 验证同名文件夹规则

```http
POST http://host.docker.internal:8080/api/file/createFolder?folderName=API-Test
cloud_disk_token: <复制的 Token>
```

第一次预期成功；使用完全相同的参数第二次发送，预期 `409` 且提示同名文件夹。这是最适合保存为回归用例的业务规则测试。

## 6. 链路测试：分片上传

在“链路”页按顺序加入：

```text
登录
→ 从响应提取 token
→ 初始化分片上传
→ 从响应提取 uploadId
→ 上传分片
→ 查询进度
→ 合并分片
```

变量配置示例：

```text
token: 登录响应中的 data.token
uploadId: 初始化上传响应中的 data.uploadId
```

后续步骤的 Header 或 Body 中使用：

```text
cloud_disk_token: {{token}}
{"uploadId":"{{uploadId}}"}
```

预期：每一步都有独立状态码、耗时和结果；链路页显示提取出的变量并对 Token 等敏感值脱敏。

## 8. 常见问题

### Docker Desktop 未启动

现象：`docker compose up` 提示无法连接 Docker Engine。  
处理：打开 Docker Desktop，等待状态变为 **Engine running** 后重试。

### Cloud Disk 接口连接失败

检查顺序：

1. 浏览器能否访问 `http://localhost:8080/v3/api-docs`；
2. Cloud Disk 的 Docker 服务是否全部 `Up`；
3. 本平台后端是否通过 Docker 运行；若是，将被测地址改为 `http://host.docker.internal:8080`；
4. 检查 8080 端口是否被其他服务占用。

### 401 鉴权失败

确认已经先调用登录接口，且 Header 名称为 `cloud_disk_token`，Token 没有复制多余空格或引号。

### 重复注册失败

这是正常现象。更换 `username` 后重试，或把“重复用户名”作为异常测试用例保存。
